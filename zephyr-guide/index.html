入門 Linux Foundation 專案 · Apache-2.0

給微控制器用的
即時作業系統

Zephyr 是一個小型、可裁剪、跨硬體的 RTOS。同一份應用程式碼，可以在 Nordic、ST、NXP、Espressif、RISC-V 等上千塊開發板上編譯執行，甚至直接在你的電腦上模擬。

~/zephyrproject
$ west build -b native_sim zephyr/samples/hello_world
-- Board: native_sim
-- Found devicetree overlay: ...
[142/142] Linking C executable zephyr/zephyr.exe
$ west build -t run
*** Booting Zephyr OS build v4.4.99 ***
Hello World! native_sim/native
1,115支援的開發板（board.yml）
14CPU 架構（ARM、RISC-V、x86、Xtensa…）
101驅動類別（drivers/ 子目錄）
4,277Devicetree binding 定義
數據來源：本 repo（VERSION 4.4.99）以 find / grep 實際統計

先搞懂：RTOS 是什麼？跟 Linux 差在哪？

RTOS（Real-Time Operating System，即時作業系統）的重點不是「快」，而是可預測：一件事情必須在規定的時間內完成，晚一點就算失敗。例如馬達控制要在 1 ms 內更新、心律裝置必須準時取樣。

微控制器（MCU）通常只有幾十 KB 的 RAM、沒有 MMU、沒有硬碟。Linux 跑不起來，而直接寫裸機（bare-metal）程式又很難管理多工、通訊協定與驅動。Zephyr 就落在這兩者之間。

裸機 Bare-metal

while(1) 超級迴圈
  • 最省資源
  • 沒有執行緒、沒有排程
  • 換一顆晶片，驅動幾乎全部重寫
  • 藍牙、網路堆疊要自己整合

Zephyr RTOS

最小約 8 KB Flash 起跳
  • 搶佔式多執行緒、確定性排程
  • 統一的驅動 API + Devicetree，換板子只改設定
  • 內建 BLE、TCP/IP、USB、檔案系統、Shell
  • 用 Kconfig 精準裁掉不需要的功能

嵌入式 Linux

通常需數十 MB RAM
  • 功能完整、生態系龐大
  • 需要 MMU 與外部記憶體
  • 開機數秒
  • 即時性需額外修補（PREEMPT_RT）

進階 02 · 架構分層

從硬體到 main()，一層一層往上疊

Zephyr 是一個「單一映像檔」系統：應用程式、核心、驅動在編譯時被靜態連結成一個 zephyr.elf。右側的 Kconfig 與 Devicetree 不是執行期的層，而是在編譯期決定每一層長什麼樣子。

進階 03 · 建置流程

west build 背後發生了什麼

Zephyr 的建置系統是 CMake，但在編譯 C 之前，會先跑兩套「設定語言」把板子與功能變成標頭檔。這是 Zephyr 與一般 C 專案最不同的地方。點選每個階段看細節。

    深入 05 · 核心機制 · kernel/

    執行緒、優先權與搶佔

    Zephyr 的排程器（kernel/sched.c）永遠讓「已就緒、優先權最高」的執行緒執行。數字越小，優先權越高。

    負數：協作式 cooperative一旦開始執行，不會被其他執行緒搶走 CPU，直到它自己 sleep、等待或 k_yield()。適合不可被打斷的協定處理。
    0 以上：搶佔式 preemptible更高優先權的執行緒一就緒，就立刻搶走 CPU。main() 預設在優先權 0 執行。
    ISR：中斷服務程序不屬於執行緒，硬體中斷會打斷任何執行緒。ISR 要短，通常只是 k_sem_give() 喚醒工作執行緒。

    執行緒之間怎麼溝通：核心物件一覽

    物件代表 API用途原始碼
    ThreadK_THREAD_DEFINE / k_thread_create建立執行緒（可在編譯期靜態定義）kernel/thread.c
    Semaphorek_sem_give / k_sem_take事件通知、計數資源；ISR 可 givekernel/sem.c
    Mutexk_mutex_lock / unlock保護共用資源，含優先權繼承避免反轉kernel/mutex.c
    Message Queuek_msgq_put / k_msgq_get固定大小資料的佇列，生產者／消費者kernel/msg_q.c
    FIFO / Queuek_fifo_put / k_fifo_get零複製傳遞不定長資料kernel/queue.c
    Eventk_event_post / k_event_wait多個旗標組合等待kernel/events.c
    Work Queuek_work_submit把工作從 ISR 推遲到執行緒中處理kernel/work.c
    Timerk_timer_start週期或單次計時回呼kernel/timer.c
    Memory Slab / Heapk_mem_slab_alloc / k_malloc固定區塊或可變大小的記憶體配置kernel/mem_slab.c, kheap.c
    延伸閱讀：啟用 CONFIG_USERSPACE 後，執行緒可以跑在使用者模式，透過系統呼叫（kernel/userspace/）存取核心物件，並由 MPU/MMU 做記憶體隔離。這是 Zephyr 相較許多小型 RTOS 的安全優勢。
    深入 06 · Devicetree 與裝置模型

    為什麼同一份 Blinky 能在上千塊板子上跑？

    答案是：程式碼裡沒有寫任何腳位號碼。硬體資訊寫在 Devicetree，編譯時被轉成巨集；驅動透過統一 API 結構體提供功能。以下追蹤 led0 從板子描述一路到你的程式。

    ①板子的 .dts 描述硬體
    boards/nordic/nrf52840dk/…dts
    aliases {
  led0 = &led0;
};
leds {
  compatible = "gpio-leds";
  led0: led_0 {
    gpios = <&gpio0 13
      GPIO_ACTIVE_LOW>;
  };
};
    ②編譯期產生巨集
    build/…/devicetree_generated.h
    /* scripts/dts/gen_defines.py 產生 */
#define DT_N_ALIAS_led0 \
  DT_N_S_leds_S_led_0
#define DT_N_S_leds_S_led_0_P_gpios_IDX_0_VAL_pin 13
...
    ③應用程式只寫別名
    samples/basic/blinky/src/main.c
    #define LED0_NODE \
  DT_ALIAS(led0)

static const struct gpio_dt_spec led =
  GPIO_DT_SPEC_GET(LED0_NODE,
                   gpios);

gpio_pin_toggle_dt(&led);
    ④驅動實作 API
    drivers/gpio/gpio_nrfx.c
    static DEVICE_API(gpio,
  gpio_nrfx_drv_api_funcs) = {
  .port_toggle_bits =
    gpio_nrfx_port_toggle_bits,
  ...
};
DEVICE_DT_INST_DEFINE(id,
  gpio_nrfx_init, ...,
  PRE_KERNEL_1, ...);
    關鍵觀念：換到 STM32 板子時，①和④換成 ST 的檔案，②自動重新產生，③你的 main.c 一行都不用改。這就是 include/zephyr/drivers/*.h 統一 API 與 dts/bindings/ 4,277 個 binding 存在的理由。

    Kconfig：決定「編進哪些功能」

    Devicetree 描述「有什麼硬體」，Kconfig 描述「要開哪些軟體功能」。repo 中共有約 2.9 萬個 config 選項。應用程式用一個 prj.conf 檔開關功能，沒開的程式碼完全不會被編譯，這就是 Zephyr 能縮到很小的原因。用 west build -t menuconfig 可以互動瀏覽所有選項。

    實作 07 · 一般使用者怎麼用

    從安裝到燒錄，六個步驟

    一般開發者不會修改 Zephyr 本身，而是把它當作 SDK：建立自己的應用程式資料夾，裡面只有 CMakeLists.txt、prj.conf、src/main.c，必要時加一個 .overlay 調整硬體設定。

    安裝工具Python、CMake、Ninja、Device Tree Compiler，以及 westpip install west
    建立工作區下載 Zephyr 與 HAL 模組west init ~/zephyrproject
    cd ~/zephyrproject && west update
    安裝 SDK各架構的交叉編譯器west sdk install
    編譯用 -b 指定板子west build -b nrf52840dk/nrf52840 app
    燒錄透過 J-Link、OpenOCD、pyOCD 等west flash
    除錯與觀察序列埠 log、Shell、GDBwest debug

    真實世界的應用場景

    穿戴裝置智慧手錶、健康手環：BLE 連手機、低功耗管理（subsys/pm）、感測器融合。
    工業物聯網感測節點：Modbus、CAN bus、LwM2M／MQTT 上雲、看門狗確保長期運作。

    附錄 08 · 名詞速查

    看到這些詞時

    west
    Zephyr 的命令列工具：管理多 repo 工作區（west.yml）、編譯、燒錄、除錯。
    Board / SoC
    板子（boards/）描述一塊實體電路板；SoC（soc/）描述上面的晶片。板子名稱格式如 nrf52840dk/nrf52840。
    Devicetree
    描述硬體的資料格式。.dts 描述板子，.overlay 讓應用程式覆寫設定，bindings 定義每種裝置可用的屬性。
    Kconfig
    來自 Linux 的功能設定系統。prj.conf 開關功能，產生 autoconf.h。
    Module
    不在主 repo 的外部程式庫（HAL、mbedTLS、LVGL…），透過 west.yml 引入，目前列出 82 個專案。
    Sysbuild
    一次建置多個映像，例如 MCUboot bootloader + 應用程式，或多核心晶片的每個核心。
    Twister
    測試執行器，自動在多個平台上編譯並執行 tests/ 與 samples/。
    native_sim
    把 Zephyr 編譯成 Linux 執行檔的「板子」，不需要硬體就能開發與測試。
    Snippet / Shield
    Snippet 是可重複使用的設定片段（如切換 console）；Shield 是外接擴充板的 Devicetree 描述。
    LTS
    長期支援版本，產品開發通常選 LTS 以獲得長時間的安全修補。
